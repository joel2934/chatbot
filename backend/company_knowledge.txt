Business Case & Problem Statement
Prepared for: Meridian Retail Group — Global Operations & Analytics
Prepared by: AI Automation Initiative

1. Executive Summary
Meridian Retail Group's operations team currently spends the majority of its analyst hours manually pulling
information from a dozen disconnected public and internal sources — shipping-route weather, competitor
pricing, supplier country/currency data, candidate screening, crypto/FX exposure, industry news, and more —
and then hand-assembling the results into PDF, Excel, and Word reports for leadership. This is slow,
error-prone, and expensive. This document lays out the problem in concrete cost terms and proposes a
single conversational AI Operations Agent, built on LangGraph, that can call all of these data sources as
tools, generate the final documents automatically, and pause for explicit human approval before doing
anything irreversible (like deleting a file).
Bottom line: the current process costs Meridian an estimated $186,800/year in analyst time and
delay-related losses. The proposed agent is estimated to cut that by roughly 70–80% within one quarter of
rollout.

4. Proposed Solution: The AI Operations Agent
We propose a single conversational agent, built with LangGraph, that exposes every data source above as a
callable tool behind one chat interface. An operator (or another internal system) simply asks in plain language

rates, and put it all in a one-page PDF for the 9am call" — and the agent plans, calls the right tools in the right
order, and produces the finished document.

4.3 Human-in-the-Loop Safety
The agent can read, write, and generate files autonomously, but file deletion always pauses the workflow
and asks a human to explicitly confirm before anything is removed. This is implemented as a genuine
LangGraph interrupt (not just a print statement) — the graph checkpoints its state, halts before the delete
executes, and only resumes once a human replies. No irreversible action ships without a person in the loop.
5. How It Works (Architecture)

1. Operator sends a request in plain English to the agent.

2. The Agent node (gpt-4o-mini) decides which tool(s), if any, are needed.

3. The Tools node executes the chosen tool(s) — weather, pricing, FX, file ops, document generation,
etc.

4. Control returns to the Agent node, which decides whether more tool calls are needed or the task is
done.

5. If the task involves delete_file, the graph interrupts and waits for explicit human approval before
continuing.

6. The Agent returns a final answer and/or a generated PDF / Excel / Word file.
The reference implementation (companion notebook: langgraph_ops_agent.ipynb) runs directly in Google
Colab, loading API keys from Colab Secrets, and includes a one-cell health check that pings every external
API listed in section 4.1 so the operator can confirm live availability before a demo.
